Reports a command that sets the scope of some signatures, but leaves a signature used by the mutable state at the overall or default scope: one that occurs in the type of a var field, other than as its owner, or that is or has a var sig.

Such a signature usually needs a scope as large as the others, or the command analyzes fewer behaviors than it seems to. In this example, Message gets the default scope of 3:

sig Node { var inbox : set Message }
sig Message {}
run bad_all_initiate {...} for 3 but exactly 3 Node

The quick-fix adds an explicit scope for the signature.
